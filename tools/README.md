# Audio tooling

Both audio packs in `assets/` are generated, not recorded. These three scripts are what
generate them, and the game reads from the same tables they do, so a pack can always be
rebuilt from the source it came from.

| Script | Produces |
|---|---|
| `render_pack.py` | `assets/vox/` — 102 voice clips + manifest |
| `sfx_render.py` | `assets/sfx/` — 23 effect clips + manifest |
| `radio.py` | the radio channel chain, used by `render_pack.py` and standalone for previews |
| `engine_proto.py` | renders the old and new thruster designs over one throttle timeline, for A/B |
| `import_sfx.py` | brings an outside clip into the pack on the pack's terms, and keeps its provenance |

Neither pack is needed to play the game. If `assets/vox/` or `assets/sfx/` is missing or
fails to load, the game falls back to live Web Audio synthesis and browser speech synthesis,
the same way it falls back to built-in ships if the models do not arrive.

## Setup

```bash
cd tools
python3 -m venv .venv            # or: uv venv .venv
.venv/bin/pip install piper-tts  # pulls numpy and onnxruntime

# The voice: en_GB-cori-medium. UK female, PUBLIC DOMAIN, and trained from scratch, so
# nothing is inherited from a restricted base model. That last part matters -- en_GB-alba
# looks clean at CC BY 4.0 but is finetuned from `lessac`, whose licence is Blizzard
# research-only, and en_US-hfc_female is CC BY-NC-SA.
mkdir -p models
BASE=https://huggingface.co/rhasspy/piper-voices/resolve/main/en/en_GB/cori/medium
curl -L -o models/en_GB-cori-medium.onnx      $BASE/en_GB-cori-medium.onnx
curl -L -o models/en_GB-cori-medium.onnx.json $BASE/en_GB-cori-medium.onnx.json
```

`ffmpeg` must be on `PATH` (used for pitch shifting via `rubberband`, and for mp3 encoding).

The virtualenv, the model (~64 MB) and render intermediates are all gitignored.

## Rendering

```bash
cd tools
.venv/bin/python render_pack.py                      # the whole voice pack
.venv/bin/python render_pack.py --only lock-1,lock-2 # just those lines
.venv/bin/python render_pack.py --quality normal     # a cleaner radio link
.venv/bin/python sfx_render.py --variants 3          # the whole effect pack
.venv/bin/python sfx_render.py --legacy              # also render the live synthesis, for A/B
```

`render_pack.py` reads the `VOX` table straight out of `../index.html`. That table is the
single source of truth: the pack cannot list a line the game does not speak, or miss one it
does, and the runtime uses the same text for its speech-synthesis fallback. Add a line to
`VOX`, re-run, done.

The manifest is always rebuilt from the `VOX` table intersected with the mp3s actually present,
never from just the clips a given run produced. That matters for `--only`: an earlier version
wrote only what it had rendered, so rendering one line orphaned the other 98. The files stayed on
disk, but the game loads the manifest — so every clip missing from it silently fell back to
speech synthesis. If a line in `VOX` has no clip yet, the run says so and leaves it out.

## The two things worth knowing before changing anything

**Every voice clip is a complete sentence.** Lines are assembled at runtime by playing clips
in sequence with a pause. A join is only inaudible where speech would have stopped anyway —
an earlier version built bearings word by word (`"bearing"` + `"zero"` + `"four"`) and the
mid-sentence seams were obvious. That is why spoken bearings are eight directional clips
rather than digits, with the exact figure left in the on-screen comms log.

**The radio chain is split in two, and the split is forced.** `radio.py transmitter` is baked
into each clip: overdrive, band-limiting, multipath comb, AGC — the equipment. The *link* —
hiss, fading, dropouts, PTT click, squelch — is simulated in the game instead, once per
transmission. Bake the keying into a clip and you get a squelch burst between every sentence.
And the noise bed has to be runtime too, because it must continue *through* a dropout: silence
where there should be static is the thing that gives it away.

`radio.py` can still render a full-chain preview for listening:

```bash
.venv/bin/python radio.py in.wav out.wav --quality weak --mode full
```

## Importing someone else's sound

Everything in `assets/` is generated by the scripts above, so nothing in the repo carries a
third-party claim, and so far nothing has needed to.

**This was tried and rejected, so start from the result.** Sixteen CC0 candidates were auditioned
against the four reward cues -- extra life, pilot recovered, pilot taken, wave start -- which are
the best case samples have in this game: one-shots, non-positional, with no parameter for
synthesis to track. The synthesis won on listening anyway. The reason is that those cues are not
really sound effects, they are music: `C6 E6 G6 C7` rising is the same key and the same timbre as
the score, so it reads as part of the mix, while a well-made interface blip from someone else's
library reads as a notification from another application. That argument applies to every cue in
the game that is pitched, and the unpitched ones were already rendered here. Audition again if you
like, but expect the same answer, and have a reason that is not "recorded sounds more real".

If an import is ever genuinely wanted, `import_sfx.py` is the way in and `imported.json` is the
ledger -- confirmed picks with author, URL and licence.

```bash
python3 import_sfx.py --from DIR --audition   # convert a shortlist into tools/build/audition
python3 import_sfx.py --from DIR              # install the ledger's clips, regenerate ATTRIBUTION.md
python3 sfx_render.py --out ../assets/sfx     # fold them into the manifest
```

`DIR` is wherever the source libraries were unpacked; the paths in the ledger are relative to it.
Auditioning takes a `slots` map of name to candidate file list, in the same shape the ledger uses.

**The licence bar is CC0 or CC BY, and the reason is the repo shape.** The pack is 23 loose mp3s
committed to a public repository, which anyone can fetch one at a time. Commercial libraries that
are otherwise free for games do not allow that: Sonniss's GDC bundle (v2.0, August 2026) permits
use in a finished project but says the licensee "may not distribute, publish, sub-license or
otherwise supply the sound effects as sound effects". Unity and Unreal projects comply because
the audio ends up inside a `.pak`; a directory of extractable files does not. The same clause
appears in Boom Library, Soundly and Zapsplat terms. Anything `-NC` is out because the game is
published, and anything `-SA` is out because ShareAlike would reach the distribution.

**Attribution is generated, not maintained.** `ATTRIBUTION.md` is written from `imported.json`
every time an import runs, so the credits cannot drift from the files. CC BY 4.0 also requires
stating what was changed, which is why the conversion steps are recorded per clip rather than
described once.

**The conversion is not optional.** Measured across the two Kenney CC0 packs, every clip peaks
between 0.87 and 1.00 while a full rendered explosion peaks at 0.42 -- a drop-in import is about
7 dB louder than the loudest thing in the game, and the audition candidates needed between 0.7
and 11.3 dB of attenuation. Pre-roll is the other half: `maximize_005.ogg` carries 237 ms of
silence before it starts, and a quarter second between the pickup and the chime reads as the
game being slow rather than the sound being long. So every import is trimmed to its measured
onset, downmixed to mono 44.1 kHz, levelled, and encoded at 64 kbps.

Levelling is decided two ways, because `loudnorm` gates on 400 ms blocks and half the interface
pack is shorter than that -- it reports `-inf` rather than a number. Clips long enough get their
integrated LUFS; the rest fall back to RMS over the sounding part of the clip. Either way the
gain is pulled back if it would breach the peak ceiling.

## Tuning

Quality presets live at the top of `radio.py` (`QUALITY`): dropout rate, noise floor, fade
depth, crackle, drive. The game ships `weak`.

For the effects, the useful knobs are at the top of each `designed_*` function in
`sfx_render.py` — crack gain, body sweep endpoints, sub level, grain counts, impulse tilt. The
whole pack re-renders in about six seconds.

Two lessons are worth repeating, because neither is obvious.

**Air absorption has to be applied to the finished mix**, not per layer. Darkened layer by
layer, the sub and body die steeply and leave bright reverb and debris with no low end beneath
them — so the composite gets *brighter* as it decays, which is backwards from a real blast.

**Vary the macro parameters, not just the noise seeds.** Three explosion variants that differed
only in their random noise measured 79% waveform-correlated — near enough to identical. Jittering
duration, sweep endpoints, decay rates and sub pitch brought that to 0.03–0.44.

## The thruster

`engine_proto.py` exists because "sounds too mechanical" needed diagnosing rather than guessing
at. The old engine was two sawtooth oscillators plus a sine sub, and measured **0.86 periodicity**
in the 30–120 Hz band: a steady pitch down there is a synthesiser, not thrust. The rewrite is
noise-dominant with three fixed high-Q chamber resonances, and measures 0.05.

The modulation matters as much as the spectrum. The old 40 / 40.7 Hz detune beat at a fixed rate
that rose with throttle — a metronome, not turbulence. Each layer is now modulated by its own
stream of heavily smoothed **noise**: a sine modulator gives a wobble the ear locks onto within a
second.

## The relay harness

`relay-test.js` drives the co-op relay over real sockets. It needs a server of its own, never
the live one:

```bash
DB_PATH=/tmp/t.db PORT=8796 GEO=0 node server/server.js &
node tools/relay-test.js 8796
```

Thirty-three checks across sectors and lobbies, the player and address caps, host authority,
the frame reader's hardening, and the co-op board's plausibility rules.

**Everything in it goes through a socket, because that is where this code's bugs have been.**
Two were caught here and neither was visible in a diff: a sector that would not reap, because
the relay's sweep ran from a close handler registered *before* the sector's own and so swept
while the leaver was still counted; and an `EventEmitter` emitting `'error'` with no listener,
which throws — a write to a peer that had just vanished failed asynchronously with `EPIPE`, the
throw landed outside every `try/catch`, and closing a browser tab mid-broadcast killed the API.

**Each client sends its own `X-Forwarded-For`.** That is how the relay sees distinct pilots in
production, since nginx sets it, and it stops the per-address cap from masking the per-sector
one — a confusion that had already turned a real test into a skipped one.

## Playing co-op locally

The two halves of co-op only meet behind a reverse proxy: `index.html` resolves its API to a
bare `/api` on localhost and `net.js` resolves the socket to a same-origin `/ws`, so without
something joining them on one port neither can be exercised. `devserve.js` is that something.

```bash
DB_PATH=/tmp/t.db PORT=8796 GEO=0 node server/server.js &
node tools/devserve.js 8777 8796
node tools/ghost-pilot.js --port 8796 --sector YAH3 --callsign WINGMAN
```

**`ghost-pilot.js` is the second pilot, and it exists because two browsers do not work here.**
Two WebGL contexts under a software renderer wedge the machine before they prove anything — the
first attempt at a two-browser test timed out three times and never rendered a frame. The ghost
joins, reads the tick like any client, and flies station on whoever else is in the sector. When a
peer fails to appear on screen, the fault is in the client rather than in whatever the other
browser happened to be doing.

Two things it taught, both now in its comments. It has to **lead** the ship it follows: a pilot
doing 40 a second leaves their last reported point behind before the next tick, so a ghost that
orbits that point sits permanently astern and never once appears on screen. And the dev proxy has
to **synthesise a per-connection address**, because in production every pilot arrives from their
own address and nginx forwards it, while locally every browser is `127.0.0.1` — four tabs would
exhaust the relay's per-address cap and the fifth would be refused for a reason that does not
exist in the real deployment.

One thing that looks like a bug and is not: **the join takes about eight seconds**. The socket is
created immediately but `onopen` cannot dispatch until the main thread finishes parsing the 1.9 MB
ship bundle. Measured: socket created at 0s, join frame sent between 5s and 10s, everything
correct from there.

### Testing the host and guest halves separately

`ghost-pilot.js --swarm 9` makes the ghost pretend to host a sortie and broadcast nine Swarm
ships. Without it the guest half is untestable, because proving a guest renders the host's
enemies needs a host that is a browser, and a guest that is a browser, at the same time.

So the two halves are proven separately, each against a real relay:

```bash
# host half -- a browser hosts, the ghost listens and counts what reaches the wire
node tools/ghost-pilot.js --port 8796 --sector ABCD --callsign OBSERVER --seconds 40
#   -> wave 1 (fight), most ships in one 4, mean 323 bytes

# guest half -- the ghost hosts a fake Swarm, a browser joins and draws it
node tools/ghost-pilot.js --port 8796 --callsign SWARMLORD --swarm 9 --seconds 300
```

Measured on the wire: **about 80 bytes a ship**, so a late wave of 28 is around 2.2 KB a
snapshot — the figure the sprint plan guessed at, now confirmed, and comfortably inside the
relay's 64 KiB frame cap.

**Headless Chromium throttles `requestAnimationFrame` on a page nobody is looking at**, to
roughly one or two frames a second, which throttles everything the game sends with it. Taking a
screenshot forces a frame, so a loop of screenshots is how a test drives the game at a usable
rate. Snapshot counts measured this way are a floor, not the real rate.

### Why the ghost shoots the furthest ship, and what it cannot test

`--attack` makes the ghost report hits against the host's Swarm, and `--swarm` makes it pretend
to host one and credit whatever is reported to it. Between them the two directions of the
damage path can be exercised without ever running two browsers.

**Against a headless host, drones ram the player and die within a second of spawning.** The
first version of this test aimed at the first ship in the snapshot and reported zero kills for
an hour, which read exactly like a broken credit path and was only ever a slow shooter: by the
time a report crossed the wire the ship had already killed itself on an idle pilot. Two things
came out of chasing it. The ghost now picks the ship **furthest from the lead pilot**, which is
the one that survives long enough for a reported hit to be the shot that finishes it. And when
nothing lives long enough to die at all, the honest signal is not the kill but the **hp field in
the next snapshot** — a reported hit that moves the host's own number for that ship proves the
path whether or not anything dies at the end of it.

What this rig still cannot reach is a browser *receiving* credit while a browser hosts, because
that needs two of them at once. The receive side is proven with a ghost standing in for the
browser, and the figure to look for is `credited N kills worth M`.
